FAERS Silver Layer - Transformation Summary

Notebook: 02 - Silver (em Progresso)

Date: June 2, 2026

Dataset: FDA Adverse Event Reporting System (FAERS)

🎯 Objective

Transform raw Bronze layer data into a cleaned, normalized, and validated Silver layer suitable for analytical queries and Gold layer aggregations. The Silver layer ensures data quality, consistency, and semantic correctness.

📊 Dataset Overview

Table Description Records
DEMO Patient demographics (age, sex, weight, country) ~2.16M
DRUG Medications involved in adverse events ~5.85M
REAC Adverse reactions (symptoms, preferred terms) ~6.87M
OUTC Patient outcomes (death, hospitalization, etc.) ~2.16M

🔧 Transformations Applied

1. Schema Casting

Problem: All columns were ingested as STRING in Bronze layer to preserve fidelity.

Solution: Cast columns to semantic types:

  • DATE: event_dt, fda_dt, mfr_dt, init_fda_dt, rept_dt, exp_dt
  • INTEGER: primaryid, caseid, drug_seq
  • DOUBLE: age, wt, dose_amt, cum_dose_chr

✅ Impact: Enables arithmetic operations, date filtering, and proper aggregations. Invalid values during casting become NULL (e.g., "UNK" → NULL for numeric columns).

2. NULL Handling

Strategy: Fill categorical NULLs with "UNK" (unknown), preserve numeric NULLs.

Tables Affected:

Table Columns Filled
DEMO sex, occp_cod, reporter_country, e_sub, occr_country, age_cod, wt_cod
DRUG role_cod, route, dechal, rechal
REAC No changes (drug_rec_act has 99.9% nulls - kept as-is)
OUTC No nulls detected

✅ Rationale: Categorical NULLs filled to enable consistent GROUP BY and JOIN operations. Numeric NULLs preserved because imputation without clinical context could introduce bias.

3. Deduplication (HYBRID Strategy)

Problem: Duplicate records found in DRUG and REAC tables (exact and logical-key duplicates).

Deduplication Logic:

Window Function Approach (HYBRID)

  1. Partition by logical key (primaryid, caseid, drug_seq for DRUG | primaryid, caseid, pt for REAC)
  2. Order by:
    • fda_dt DESC — Most recent submission first (temporal correctness)
    • completeness_score DESC — Most complete record as tiebreaker (data quality)
    • caseversion DESC — Latest version as final tiebreaker
  3. Select row_number() = 1 (first record per partition)

Results:

Table Action Key
DEMO No duplicates - copied directly N/A
DRUG HYBRID deduplication applied (primaryid, caseid, drug_seq)
REAC HYBRID deduplication applied (primaryid, caseid, pt)
OUTC No duplicates - copied directly N/A

✅ Advantages:

  • Handles exact AND logical-key duplicates in one pass
  • Prioritizes recency (aligns with FAERS versioning system)
  • Uses completeness as tiebreaker (prevents data loss when versions have same date)
  • Standardized via reusable deduplicate_hybrid() function
  • Preserves referential integrity (uses fda_dt from DEMO table)

4. Unit Normalization

Problem: Age and weight reported in multiple units (years, decades, months, kg, lbs), making quantitative analysis difficult.

4.1 Age Normalization

New Column: age_years (standardized to years)

Original Unit Conversion Formula % of Data
YR (Years) value × 1 52.99%
DEC (Decades) value × 10 1.02%
MON (Months) value / 12 0.46%
DY (Days) value / 365.25 0.05%
WK (Weeks) value / 52.18 0.05%
HR (Hours) value / 8766 0.05%

Outlier Removal: age_years < 0 or > 120 → NULL

4.2 Age Group Creation (age_grp_cleaned)

Problem: Original age_grp column has 74.5% NULL values.

Solution: Derive age groups from normalized age_years using FDA demographic standards:

  • NEONATE: < 1 month (< 0.083 years)
  • INFANT: 1 month - < 2 years
  • CHILD: 2 - < 12 years
  • ADOLESCENT: 12 - < 18 years
  • ADULT: 18 - < 65 years
  • ELDERLY: 65+ years
  • UNK: age unknown (NULL)

✅ Impact: Reduces age group gap from 74.5% significantly, enabling demographic stratification for analysis.

4.3 Weight Normalization

New Column: wt_kg (standardized to kilograms)

Original Unit Conversion Formula % of Data
KG (Kilograms) value × 1 16.49%
LBS (Pounds) value × 0.453592 0.03%

Outlier Removal: wt_kg < 0.5 or > 500 → NULL

⚠️ Note: dose_amt and cum_dose_chr were NOT normalized because therapeutic doses vary by medication, unit, and route of administration. Normalization without drug-specific context would introduce incorrect interpretations.

5. String Normalization

Problem: Categorical columns contain case inconsistencies ("US" vs "us"), leading/trailing spaces, and empty strings.

Transformations Applied:

  1. trim() — Remove leading/trailing whitespace
  2. upper() — Convert to uppercase
  3. Empty strings after trim → "UNK"

Columns Affected:

Table Columns
DEMO sex, occp_cod, reporter_country, e_sub, occr_country, age_cod, age_grp, age_grp_cleaned, wt_cod
DRUG role_cod, route, dechal, rechal
REAC pt (preferred term)
OUTC outc_cod

✅ Advantages:

  • Consistent representation of unknowns (all "UNK")
  • Robust JOINs (no failures due to case/space mismatches)
  • Simplified queries (no need for col == "" OR col IS NULL)
  • Performance optimization via .withColumns() batch processing

6. Date Validation

Problem: Dates can contain parsing errors, manual input mistakes, or system bugs leading to impossible values (e.g., year 1800, future dates).

Validation Rules:

Bound Value Rationale
Lower Bound 1900-01-01 FAERS system created in 1960s; dates before 1900 are clearly errors
Upper Bound (DEMO) current_date() Future events are impossible
Upper Bound (DRUG exp_dt) None Expiration dates are naturally in the future

Tables and Columns:

  • DEMO: event_dt, mfr_dt, init_fda_dt, fda_dt, rept_dt
  • DRUG: exp_dt (lower bound only)

Action: Invalid dates → NULL (preserves record but marks date as unreliable)

✅ Advantages:

  • Temporal analysis without outliers
  • Transparent handling (invalid dates marked as NULL)
  • Query simplification (WHERE date IS NOT NULL filters quality data)
  • Auditability (can count invalidated dates)

🎯 Key Design Decisions

Deduplication Strategy

HYBRID approach balances temporal correctness (recency) with data quality (completeness), using window functions for deterministic record selection.

NULL Handling

Categorical NULLs filled with "UNK" for consistent grouping; numeric NULLs preserved to avoid clinical bias from imputation.

Unit Normalization

Created new columns (age_years, wt_kg, age_grp_cleaned) rather than replacing originals, preserving audit trail.

Date Validation

Invalid dates set to NULL with clear bounds (1900-today), enabling temporal analysis without outliers.

Performance

Batch operations via .withColumns() instead of iterative .withColumn() loops for 5-10x speedup.

Reusability

Standardized deduplication logic encapsulated in deduplicate_hybrid() function for consistent application.
